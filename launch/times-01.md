## FRONT PAGE — The bill arrives
Three ordinary questions were put to a coding agent on a production codebase this week, twice each. The first time the agent searched the way agents do: open candidates, read them, keep going. The second time a local index answered "where is it" first and the agent read only the passage. Same answers, same file-and-line pointers. Bytes loaded into context: 103,023 against 6,405; 243,640 against 6,389; 241,859 against 5,101. Sixteen, thirty-eight and forty-seven times.

The AI Burn Clock, launched Tuesday, prices the habit against budgets that organisations published themselves. Every factor is a slider. Every source is a link. The argument is with a factor, not with the index.

## THE REMEDY, IN THREE STEPS
Index once. Ask "where" first. Read only that. The engine measured is XERJ, open source under Apache-2.0, one binary, Elasticsearch-compatible on port 9200, running on the developer's machine. Four commands, no cloud key. A Claude Code plugin prints a score card at the end of every session. github.com/xerj-org/xerj

## THE SEVEN-DAY TOKEN DIET
Install the plugin, work as usual for seven days, post the card. Lowest read-to-used ratio wins and takes this column next Friday. Rules and leaderboard: aiburnclock.org/diet

## UNPLUGGED
A 3-billion-parameter model on a laptop, a local index, a 120-line loop, and the Wi-Fi off: the agent still answers "where is X" with file and line, because the index, not the model, does the finding. The configuration a ship, an embassy or a hospital needs. github.com/nikolaichuk7/xerj-offline
